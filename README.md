## Хэсэг A — Category-Partition (POST /transfer)

### Олон алдааны давуу эрэмбэ

Нэг хүсэлтэд хэд хэдэн алдаа зэрэг байвал **from → to → amount** дарааллаар эхний алдааг буцаана:
`ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO → ERROR_SAME_ACCOUNT → ERROR_BAD_AMOUNT → ERROR_INSUFFICIENT → ERROR_LIMIT`.
**Үндэслэл:** from данс байхгүй/царцаасан бол үлдэгдэл, лимитийг шалгах боломжгүй тул эхлээд дансуудыг, дараа нь дүнгийн формат (≤ 0), хамгийн сүүлд хөрвүүлэлт хийсний дараах үлдэгдэл → лимитийг шалгах нь хүсэлтийн талбарын дараалал ба хямдаас үнэтэй шалгалт руу явах логиктой нийцнэ.

### A1 — Сонголтууд ба төлөөлөх утгууд

Орчны таамаглал: данс A — MNT, үлдэгдэл 1,000,000₮, өдрийн лимит 2,000,000₮; ханш 1 USD = 3,500₮.

| Параметр / сонголт | Утга | Төлөөлөх утга (жишээ) |
|---|---|---|
| **from** — данс байгаа эсэх, төлөв | Valid | `A` (идэвхтэй, MNT) |
| | Frozen | `F` (царцаагдсан данс) |
| | Missing | `X999` (байхгүй ID) |
| **to** — данс байгаа эсэх, from-оос ялгаатай эсэх | Valid | `B` (идэвхтэй, MNT) |
| | Missing | `Y999` (байхгүй ID) |
| | SameAsFrom | `to = from = A` |
| **amount** — тэмдэг, үлдэгдэл/лимиттэй харьцуулалт (хөрвүүлсний дараа) | Normal | 100,000₮ |
| | ExactBalance | 1,000,000₮ (= үлдэгдэл, хязгаарын утга) |
| | Zero | 0 |
| | Negative | −500 |
| | OverBalance | 1,000,001₮ (үлдэгдлээс 1-ээр их, лимит дотор: лимит 5,000,000₮ болгосон) |
| | OverLimit | 2,000,001₮ (үлдэгдэл дотор: үлдэгдэл 5,000,000₮, лимитээс 1-ээр их) |
| **currency** — дансны валюттай ижил эсэх | Same | `MNT` |
| | Different | `USD` (ханшаар хөрвүүлнэ) |
| **DailyUsed** — *далд орчны сонголт*: өнөөдөр лимитээс хэр ашигласан | None | 0₮ ашигласан |
| | Partial | 1,500,000₮ ашигласан (үлдсэн лимит 500,000₮) |

**Далд орчны сонголт:** хүсэлтийн body-д харагдахгүй ч үр дүнд нөлөөлдөг — өдрийн лимитийн ашиглалт (DailyUsed), дансны үлдэгдэл, ханш. Үлдэгдэл/ханшийг amount-ын утгуудад (OverBalance, Different) шингээж, лимитийн ашиглалтыг тусдаа сонголт болгосон.

### A2 — Хязгаарлалтууд

| Утга | Тэмдэглэгээ | Үндэслэл |
|---|---|---|
| from = Valid | `[property fromOK]` | Үлдэгдэл/лимит шалгалт зөвхөн хүчинтэй from данстай утгатай. |
| from = Frozen | `[ERROR]` | ERROR_FROZEN буцаана — бусад утгатай хослуулах нь алдааг нууна (masking). |
| from = Missing | `[ERROR]` | ERROR_NO_FROM — нэг тестээр хангалттай. |
| to = Valid | `[property toOK]` | Шилжүүлэг явагдах нөхцөл. |
| to = Missing | `[ERROR]` | ERROR_NO_TO — бусад нь хүчинтэй үед нэг удаа. |
| to = SameAsFrom | `[ERROR]` | ERROR_SAME_ACCOUNT — нэг удаа. |
| amount = Zero, Negative | `[ERROR]` | ERROR_BAD_AMOUNT (amount ≤ 0) — валют/лимиттэй хослуулах шаардлагагүй. |
| amount = ExactBalance | `[SINGLE]` | Хязгаарын (boundary) утга, нэг удаа шалгахад хангалттай. |
| amount = OverBalance, OverLimit | `[IF fromOK AND toOK]` | Үлдэгдэл/лимитийг хөрвүүлсний ДАРАА шалгадаг тул currency-тай хослуулах нь сонирхолтой, харин данс буруу үед утгагүй. |
| currency = Different | `[property converted]` | Хөрвүүлэлт хийгдэнэ — OverBalance/OverLimit-тэй хослуулна. |
| DailyUsed = Partial | `[SINGLE]` | Лимит хэтрэлтийг OverLimit утга аль хэдийн илэрхийлдэг; хагас ашигласан лимиттэй хэвийн шилжүүлэг нэг удаа хангалттай. |

**Тооцоо:**

- Бүрэн олонлог: from(3) × to(3) × amount(6) × currency(2) × DailyUsed(2) = **216**
- Хязгаарлалтын дараа:
  - [ERROR] утгууд тус бүр 1 удаа: Frozen, Missing(from), Missing(to), SameAsFrom, Zero, Negative = **6**
  - [SINGLE] утгууд тус бүр 1 удаа: ExactBalance, Partial = **2**
  - Үлдсэн: from=Valid(1) × to=Valid(1) × amount∈{Normal, OverBalance, OverLimit}(3) × currency(2) × DailyUsed=None(1) = **6**

**216 → 14**

## Хэсэг B — PICT

Моделийн файлууд: [browser.model](browser.model), [transfer-nc.model](transfer-nc.model), [transfer.model](transfer.model), [transfer-neg.model](transfer-neg.model). Бүгдийг `/r` хэрэглэхгүй, анхдагчаар ажиллуулсан. Мөрийн тоог `tail -n +2 results/<файл>.txt | wc -l`-ээр тоолсон.

### B1 — Браузерын жишээ

| Хувилбар | Мөрийн тоо | Файл |
|---|---|---|
| Бүрэн олонлог (3·3·2·2·2·2) | 144 | — |
| Лекц дээр гараар (2-way) | 9 | — |
| PICT 2-way | **10** | [results/browser-2way.txt](results/browser-2way.txt) |
| PICT 3-way (`/o:3`) | **20** | [results/browser-3way.txt](results/browser-3way.txt) |

**Greedy-гийн тайлбар:** PICT 2-way-д 10 мөр өгсөн нь лекцийн гарын 9 мөрөөс 1-ээр их. PICT нь greedy алгоритмаар мөр бүрийг "одоогоор хамрагдаагүй хамгийн олон хосыг хамрах" зарчмаар нэг нэгээр нь нэмдэг тул эхний сонголтууд нь дараа нь илүүдэл мөр шаардах байдалд хүргэж болох бөгөөд хамгийн цөөн (оптималь) covering array-г заавал олдоггүй. Content×Cookies (3×3 = 9) хос дангаараа 9 мөрийн доод хязгаар тавьдаг ч, үлдсэн 4 хоёртын параметрийн хосуудыг тэр 9 мөрөнд яг багтаах нь хайлт шаарддаг — greedy түүнийг алгасаж 10 гаргасан.

**3-way:** 20 мөр — бүрэн олонлог 144-ийн ~14%; 3 параметрийн бүх гурвалыг хамарсаар 7 дахин цөөн тест.

### B2 — Шилжүүлгийн модель

- `transfer-nc.model` — A-гийн сонголтууд, хязгаарлалтгүй.
- `transfer.model` — A2-ын [ERROR]/[SINGLE]/[IF] хязгаарлалтыг `IF … THEN …` болгон буулгасан.
- `transfer-neg.model` — алдаа буцаадаг утгуудыг `~` (negative) гэж тэмдэглэсэн, хязгаарлалтгүй.

| Модель | Мөрийн тоо | Happy path мөр (бүх утга хүчинтэй) | Нэг мөр дэх алдааны тоо (мөрийн тоо) |
|---|---|---|---|
| transfer-nc | **18** | 0 | 1 алдаа: 6, 2 алдаа: 6, 3 алдаа: 6 |
| transfer | **13** | 3 | 0: 3, 1: 10 |
| transfer-neg | **22** | 5 | 0: 5, 1: 17 |

(Алдаа гэж Frozen, Missing, SameAsFrom, Zero, Negative, OverBalance, OverLimit утгуудыг тооцсон.)

**Ажиглалт:**

- **transfer-nc:** Happy path мөр нэг ч гараагүй, 12 мөрөнд 2–3 алдаа зэрэг орсон (жишээ нь `Frozen Missing OverBalance Different`). Ийм мөр бодит дээр зөвхөн эхний алдааг (бидний эрэмбээр ERROR_FROZEN) шалгах ба Missing(to), OverBalance нь нуугдана (error masking) — тиймээс мөр юуг шалгаж буй нь тодорхойгүй, хосын хамралт "цаасан дээр" л байна.
- **transfer:** A2-ын хязгаарлалтаар мөр бүрт ≤ 1 алдаа, 3 happy path мөр гарсан. 13 мөр нь гарын 14 фреймээс 1-ээр цөөн: pairwise нь `Valid Valid Normal Same None` гэсэн цэвэр happy path-ийг тусад нь шаардахгүй, учир нь түүний бүх хосууд (Normal×Same, Same×None гэх мэт) алдааны мөрүүдэд аль хэдийн хамрагдсан.
- **transfer-neg:** `~` нь мөр бүрт хамгийн ихдээ нэг сөрөг утга оруулж, 5 цэвэр эерэг мөр гаргасан — error masking арилсан. Гэхдээ 22 мөр болж хамгийн олон: сөрөг утга бүрийг эерэг утга бүртэй хослуулдаг (жишээ нь `~Frozen × Different × None`, `~Missing × ExactBalance`) — эдгээр нь A2-ын [ERROR] дүгнэлтээр утгагүй хослолууд.

**`~` хэрэглэхэд A2-ын хязгаарлалт хэрэгтэй хэвээр үү?** Хэсэгчлэн. `~` нь [ERROR]-ын "нэг мөрөнд нэг алдаа" гэсэн утгыг хангадаг тул олон алдааны хязгаарлалт шаардлагагүй болсон. Харин [SINGLE] (ExactBalance, Partial-ийг нэг удаа) ба "алдааг бусад энгийн утгатай ганц удаа" гэсэн хэмнэлтийг `~` илэрхийлдэггүй — сөрөг утгыг эерэг бүх утгатай хослуулах тул мөр олширно (22 > 13). Тиймээс SINGLE/IF хязгаарлалтыг `~`-тэй хамт хэрэглэх нь зүйтэй.

## Дүгнэлт

Category-partition арга нь тодорхойлолтоос сонголт, төлөөлөх утгыг гаргаж, [ERROR]/[SINGLE]/[IF] хязгаарлалтаар 216 хослолыг 14 утга учиртай фрейм болгож багасгасан. Энэ арга алдааны семантикийг сайн барьдаг — мөр бүр яг нэг зүйлийг шалгаж, oracle нь тодорхой байдаг. PICT нь хосын хамралтыг баталгаажуулж, браузерын жишээнд 144-ийн оронд 10 (2-way) ба 20 (3-way) мөр гаргасан ч greedy учраас гараар олсон 9 мөрөөс илүү гарсан. Хязгаарлалтгүй transfer-nc моделд happy path огт гараагүй, мөрийн 2/3 нь олон алдаатай байсан нь error masking-ийн бодит жишээ болсон. `~` сөрөг утга нь энэ асуудлыг шийдэж мөр бүрт нэг алдаа үлдээсэн ч мөрийн тоог 22 болгож өсгөсөн. A2-ын хязгаарлалттай transfer.model хамгийн цөөн буюу 13 мөр өгч, гарын 14 фреймтэй бараг давхцсан нь хоёр арга бие биеэ нөхдөгийг харуулсан. Тиймээс хамгийн сайн арга нь эхлээд category-partition-аар хязгаарлалтаа гаргаад, түүнийгээ PICT-ийн хэл рүү буулгаж автоматаар хамралт үүсгэх юм.A2 — аль утгыг [ERROR] гэж тусгаарлах, аль нь (OverBalance, OverLimit) валюттай хослох ёстойг шийдэх нь хамгийн их ажилгаатай алхам байлаа, учир нь хэт их хязгаарлалт жинхэнэ сонирхолтой хослолыг устгадаг. Мөн тодорхойлолтод бичигдээгүй олон алдааны давуу эрэмбийг өөрөө тогтоох нь давхар нөхцөлийн oracle-ыг бүхэлд нь тодорхойлсон чухал шийдвэр болсон.
